# CI of 21ec256 (v27.0.1)

v27.0.1's release run passed, but CI on main and on the tag failed: 8 test files on Linux (Debug, sanitizers, Eigen's solvers) and 2 on macOS 15 (Release, no Accelerate LU). Since the pushes of 17 October no CI run had been green. Each failure was read from the run's log (run 39038215297), reproduced here where it could be, and fixed before the tag moved.

## A real fault: Eigen's LU given another pattern

**Failure.** `test_fem_sparse aPatternThatChanges`:
- Linux: AddressSanitizer, a heap-buffer-overflow in `Eigen::SparseLU::factorize`;
- macOS 15: a SIGSEGV after 0.19 s.

**Why.** The sparse LU's wrapper (5e4a02f) handles a matrix whose pattern changes, as a Newton Jacobian's entries come and go:
- On Accelerate's backend it analyses the union again. That is the only one this Mac runs at the test's sizes, so the test never saw the other.
- On Eigen's backend it factorized the new matrix in the old analysis, and Eigen wrote past its arrays.

Eigen's backend is the one everywhere Accelerate's LU is not: Linux, Windows, macOS before 26, and below 20,000 unknowns on macOS 26 too.

**Now.** The wrapper keeps the pattern Eigen analysed and analyses again when a matrix's size or pattern differs: six analyses for the test's six changes, where it made one.

**The test** runs the sequence on each backend (Eigen's, then the platform's), so a Mac catches it too. Under the sanitizers here: 11 of 11, no report.
