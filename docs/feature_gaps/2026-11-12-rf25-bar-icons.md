# RF 2.5D's view tools as the layout viewer's icons

The user: "change "Zoom extents", "Ruler", "Read the layout again" to buttons with images similar to the bottons in the
gds layout viewer and move them to the right side of the marker button. for the "Read the layout again" use a "reload"
button."

## What changed

- **The RF 2.5D tab's bar.** Its three word buttons at the start are gone. After the pen (the marker) at the bar's end,
  there are now three icon buttons, in this order:
  - **Zoom Extents** (`rfFit`), with the layout viewer's fit picture;
  - **Ruler** (`rfRuler`), with its ruler picture, checkable as before;
  - **Read the Layout Again** (`rfReread`), with a new reload picture: a circle's arrow turning clockwise.

  Each keeps its object name and what it does. Its tool tip now starts with its old name.
- **`LayoutDoc` shares its toolbar look:**
  - `toolIcon(ToolIcon)` gives the Fit, Ruler and new Reload pictures, drawn in the text's colour of the moment;
  - `makeToolButton()` makes a button one of its toolbar's: a 16-pixel icon, flat until hovered, taking no focus;
  - `toolButtonRules()` is the style sheet for those buttons, hovered and checked. The layout tab's own `restyle()`
    uses it.
- **The style sheet is set on each of the four buttons**, the pen included, not on the bar. Set on the bar, it drew the
  bar's word buttons square and took Draw's frame away. The sheet is set again when the palette changes.

## Checked

- **`test_rf25_doc` `theRulerMeasuresTheLayout`** now also checks:

  - each is a layout tool button, the three with 16-pixel icons and no words;
  - the bar itself has no style sheet;
  - the three pictures differ from one another;
  - Read the Layout Again starts a read.
- **`test_qucs_control` `anRf25ModelsPenIsReadThroughTheTools`** had the pen as the bar's last widget. It now checks

  four lints pass.
- On the Cocoa platform, the bar was grabbed next to a layout tab's: the same pictures and the same flat look, and the
  checked Ruler highlighted as there.
