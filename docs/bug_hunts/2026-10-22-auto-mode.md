# Bug hunt: the tools allowed in auto mode, and the day's other changes

*22 October 2026 - Qucs-S 27.0.3, `e39ae3e` (the Release build). In the foreground, hunting from 15:22
to 15:45, the write-up after. The probes are calls through the real MCP server and
`QucsControl` in a throwaway test, [2026-10-22-auto-mode/zz_hunt.cpp](2026-10-22-auto-mode/zz_hunt.cpp).
It was registered for the hunt only. The findings are written up as they came; none is fixed here.*

The user's request: "continue for hunting more bugs for one hour".

The hunt looked first at what changed last:
- `e39ae3e`: Qucs-S's tools allowed in auto mode without Claude Code's own check, the dock's own
  questions, the restarts on a mode change;
- `77ef143`: `get_state`'s projects by name, a PDF's tools in every turn;
- `87e3d9e`: the panel drawn in parts.

The main question: can a tool that auto mode now lets through lose or change something, unasked, that
`irreversible()` does not see?

Each probe ran in a temporary folder with its own settings. The probes run no command: the schematic of
A1 has no analysis, and nothing simulates it.

A1, A2, A3 and A5 make auto mode, as `e39ae3e` set it up, less safe than before it for the commands a
schematic carries and for files outside the workspace. Until they are fixed, the dock's tools should be passed in
auto mode only once the dock asks about such uses. A1 first.

## A. Wrong or unsafe without a word

**A1. Commands a schematic carries, run in auto mode with no question.**
`QucsControl::commandsRefused()` refuses them only "with the Simulator Settings' check of commands on".
That is off by default (`settings.cpp`, `CheckCommands` false). The design leaned on the client's
permission prompt showing `allow_commands`. In auto mode since `e39ae3e`, nothing shows it.

Probe M opened a schematic with one System Command part (`echo qucs-test`) and no analysis, and asked
the predicates. Nothing was simulated.
- `simulate` and `tune`: in `autonomousTools()`; `irreversible()` 0; `askedEachTime()` empty, with or
  without `allow_commands`.
- A batch holding `simulate` of it: the same.
- `CheckCommands`: 0.
- `add_component` with type `CMD`: placed (as a preview here). A System Command part with its `cmd`
  property can therefore be made by a tool that auto mode allows.

So "simulate this schematic I downloaded" runs whatever it carries, with the user's rights, and nothing
asks. A model can also build such a schematic and simulate it. The dock asks about every line typed into
a console for this very reason (`askedEachTime`).

*Proposed fix:* `askedEachTime(simulate | tune, args)` should be non-empty when the schematic it would
run carries commands (`erc::commandsRun()`), whatever `CheckCommands` says. A batch is then covered
through its calls. The dock then asks about it in auto mode too.

**A2. Files written anywhere by tools allowed in auto mode.**

Probe L (paths outside the workspace):
- `new_document` (text), `edit_text` with any lines, and `save_document` with `as`
  `outside/LaunchAgents/agent.plist` made the file with that text.
- An existing `outside/dot_zshrc` opened with `open_document`, its `PATH` line replaced by `edit_text`,
  and saved with `save_document` was written as edited.
- `irreversible()` was 0 for each save, as it is for `export_netlist` to a new file outside
  (probe L3).

All of these tools are in `autonomousTools()`, so in auto mode nothing checks them. Claude Code's own
auto mode checks writes outside its working folder.

Where the dock allows the host's tools unasked (Allow all, Accept Edits), the same writes went unasked
before `e39ae3e`. The dock's own policy is wider than Claude Code's Accept Edits, which accepts edits
inside the working folder only.

*Proposed fix:* a host predicate for a use that writes outside the workspace and the open project
(`save_document` to its own file or `as`, `export_*`, `copy_document`, `create_subcircuit`, the
synthesis tools' `save_as`, `fem_model` save, `fem_export`). `asksItself()` holds such a use in auto
mode, and `hostAllowsUnasked()` asks about it where only edits are free.

**A3. `fem_export` writes over any file its node names.**
`QucsControl::femExport()` calls `MultiphysicsDoc::runExport()`, which writes the node's `file` with no
look at what is there. Probe I, the coax example solved:
- `ts1`'s `file` set (by `fem_edit`) to `keep.s2p`, a file already there: written over, 9 → 1541 bytes;
- then set to `c.sch`, a schematic open in the window with unsaved changes: written over with the
  touchstone, 218 → 1541 bytes. The open tab kept its unsaved edits, over a file that is no longer a
  schematic.

`irreversible("fem_export", ...)` is false, and cannot be otherwise: the target is the model's, not
the call's. `export_netlist`, by contrast, refuses an open document as its target, and a schematic,
symbol, data display or code file unless `replace` is given (probe G).

*Proposed fix:* `runExport()` should refuse a target open in a tab, or a Qucs-S document or code file
that is not an earlier export of this node, unless the call says `replace`. `irreversible()` should
look the node's file up for `fem_export`, as it does `close_document`'s document.

**A4. A mode switch between turns kills a background task.**
`Session::setPermissionMode()` (`e39ae3e`) stops the program at once when the auto-mode tools change
and no turn is under way. Probe J used a fake program whose turn ends with a task left in the background
(`task_started`, `is_backgrounded`): after the turn it was running; switched to auto, it was stopped, and
no notice was given. A long build or simulation the user sent to the background (Ctrl+B) is killed this
way. A host call sent to the background loses its result; there `processFinished()` at least says so.

Bypass mode did the same before (it is taken only at the program's start).

*Proposed fix:* restart when idle - no background task or background host call - and meanwhile
`asksItself()` covers the mode, as it does during a turn.

**A5. Files read anywhere.**
Probe S: a file `outside/.aws/credentials` was opened with `open_document`, and `get_text` returned its
lines. `open_document` is in `autonomousTools()` and `get_text` among the reading tools, so in auto mode
nothing checks it. Before `e39ae3e` the program's own check saw `open_document`.

*Proposed fix:* as A2's, for reading. A document opened from outside the workspace and the open project
is asked about where Claude acts on its own.

**A6. A save over an outside change.**
Probe T:
- `notes.txt` was edited by `edit_text`, then a line was added to its file elsewhere. `save_document`
  wrote the document over it, and the added line was gone.
- A model was given a parameter by `fem_edit`, then its file was changed elsewhere. `fem_model` save
  wrote over the change.
- `irreversible()` was 0 for both saves.

`save_document` refuses a schematic in this state unless `replace` is given.

*Proposed fix:* the same conflict check for text documents and models, and `irreversible()` true where
`replace` writes over it.

## B. Less than right

**B1. `get_state`'s project entries are not taken back.**
Probe N, a workspace with `alpha_prj`: `get_state` lists `["alpha (folder alpha_prj)"]`.
- `open_project` with that name: "There is no project alpha (folder alpha_prj)";
- `list_documents` with that folder: "There is no folder or project ...".

The `{name, folder}` objects of before could be passed on as they were.

*Proposed fix:* list the folders' own names (`alpha_prj`), which both tools take. They are as short, and
the name is that without `_prj`. Linked projects go in a field of their own.

**B2. Long runs in the chat's transcript.**
Probe U, a reply of one run of letters in the 440-pixel panel:

| letters | render |
|---|---|
| 8,000 | 20 ms |
| 16,000 | 47 ms |
| 32,000 | 140 ms |
| 64,000 | 459 ms |
| 128,000 | 1,612 ms |

The same, quoted or in a code block, to the millisecond. While such a reply streams, each piece's render
lays the run out again. The Markdown viewer gives runs past 64 letters a zero-width break (`a856e00`,
C2); the chat's `renderMarkdown()` (through `markdown::setMarkdown`) does not.

*Proposed fix:* the viewer's breaks in the chat too, taken out on copy as the viewer does.

## Notes

**N1.** The question for a batch held by the dock says "This cannot be undone: files are deleted or
written over, or unsaved changes discarded" under the batch's tools. The call that cannot be undone, and
its file, would say what is at stake.

**N2.** `fem_export` with `copy` replaces the clipboard with its RLCG part. It is allowed in auto mode,
and the user's own clipboard is lost.

## Checked and found right

- **`open_document` and `show_document`** of a schematic with unsaved changes, whose file changed on
  disk: the unsaved edits kept (probe C).
- **`import_data`** with the name of a simulation's dataset, or one it did not import: refused,
  "it would be written over" (B, B2).
- **`export_netlist`** to an open schematic: refused, even with `replace`. To a closed one with
  `replace`: `irreversible()` true (G).
- **`copy_document`** into a folder holding the name: refused without `replace` (H).
- **The synthesis tools' `save_as`** naming a file that is there: not written. `save_document`'s own
  question was cancelled, and the answer says "not saved" (A, A2).
- **A model.**
  - Closed with `discard` after an unsaved edit: `irreversible()` true (D).
  - Opened again with `fem_model open` while open with unsaved edits: the edits kept (E).
- **`new_document`** `data_display` over a `.dpl` it cannot read: refused, the file kept (F).
- **`undo` with `files`** after the user changed the file a call wrote: "not put back ... (changed since
  export_netlist)" (P).
- **`new_project`** with `../escaped`, `sub/inner` or an absolute path: refused, "has a slash"; nothing
  made outside the workspace (Q).
- **The panel through a switch to auto between turns:** "ready", and the note "Permissions: Auto, from
  the next prompt on." (O).
- **Images:** the transcript resolves no relative image path, so `87e3d9e`'s image stamps miss none of
  them.
- **One undo per call:** each of these, called on a schematic, was undone by one `undo`, the schematic as
  before (W): `arrange`, `set_schematic`, `create_subcircuit`, `replace_component`, `rename_net`, `move`,
  `delete`, `add_component`, `edit_component`, `connect`, `add_painting`, `probe`, `add_diagram`,
  `synthesize_attenuator` placed in it. `add_analysis` with a plot takes two, as its answer says
  ("steps to undo": 2).
- **`make_symbol`** over a symbol drawn by hand: one `undo` brings the drawing back (V).
- **The dock with the real host, in auto mode:** a `close_document` discarding unsaved changes is held.
  Its card says "This cannot be undone ...", Deny leaves the document open, and the program is answered
  "The user did not allow this." (X).
- **A display's Octave script** runs after a simulation only, not on opening it.
- **`fuzz-sch.py`:** 400 mutants of the 252 examples, seed 2210: 800 runs, no failure.

## Reproducing

[zz_hunt.cpp](2026-10-22-auto-mode/zz_hunt.cpp) is a QtTest of its own. To run it:
1. Copy it to `qucs-s-26.1.1/qucs/tests/`.
2. Add `qucs_add_test(zz_hunt)` to that folder's `CMakeLists.txt`.
3. Build it, and run it with `QT_QPA_PLATFORM=offscreen QUCS_CLAUDE=/nonexistent/claude
   QUCS_GH=/nonexistent/gh`.
